# TurkStat (TÜİK) Work Allocation Tool

A login-free, server-less web tool that runs entirely in the browser. It bundles two independent engines, selectable from the home page:

| Engine | Purpose |
|---|---|
| **v1 – Work Allocation Engine** | Distributes jobs (`isler.csv`) to field staff (`calisanlar.csv`) according to capacity and rules, with pre-approval, manual edits, a process report and sharing packages. |
| **v2 – Notebook Rotation Engine** | Builds a yearly monthly rotation plan for *N* staff and *N* notebooks ("defter"), with equality, repeat and follow-up constraints, staff leave, and a validator. |

**Privacy:** all files are parsed and processed in the browser. Nothing is uploaded to a server and there is no sign-in. Shared files (CSV/ZIP/HTML) are generated locally.

**Languages:** Turkish (default), English, French, German, Japanese, Simplified Chinese. Switch from the selector in the header; the choice is remembered in the browser.

## Quick start

```bash
npm install --legacy-peer-deps   # vitest has a peer-dependency conflict with @types/node
npm run dev                      # http://localhost:3000
npm test                         # unit tests (engines, CSV validation, i18n consistency)
npm run lint
npm run build
```

Requires Node.js 20+. Sample data lives in `public/ornek/` (generated by `scripts/ornek-veri.mjs`); the app can load it with one click.

## v1 – Work Allocation Engine

Flow (9 screens): Welcome → Staff & capacity → Rule selection → Job upload & validation → Allocation → Pre-approval → Approval & output → Process report → Summary & sharing.

- **Excel-style preview** of uploaded CSVs (column letters, row numbers, formula bar, sheet tab, status bar). A checkbox at the start of every row lets the user decide which rows are used.
- **Capacity model:** effective capacity = period capacity × availability %. Unit is "interview points" (rural jobs weighted by a multiplier) or job count; modes: hard limit or proportional target.
- **Rules** (mandatory or preferred, with priority order): province matching, neighbourhood grouping, capacity-proportional balance, rural/urban condition, previous-month repeat (rotation or continuity).
- **Pre-approval:** per-employee fill bars, manual "move to another employee" with capacity/rule checks, unassigned jobs with reasons.
- **Outputs:** `atama_sonucu.csv`, `atanamayan_isler.csv`, `kural_ozeti.json`, updated `calisanlar.csv`; a process report (timeline built from an event log, rule-compliance rates, charts) exportable as PDF (print), HTML, JSON and CSV; per-employee and per-province packages, message/e-mail templates and a full ZIP, each with a privacy notice before download. The per-employee files never contain other employees' jobs.
- Every approval and download goes through a modal confirmation dialog.

## v2 – Notebook Rotation Engine

A constraint-based backtracking search inspired by Sudoku solvers (fewest-options-first, reachability pruning, seeded restarts). Plan representation: for each month, which person holds each notebook.

Rules:

| Code | Rule | Type |
|---|---|---|
| K1 | A notebook does not return to the same person within the next *G* months (default 2) | mandatory |
| K2 | Each ordered hand-over pair (A→B) repeats at most a limit per year (auto = theoretical lower bound, relaxed by +1 and reported if needed) | mandatory |
| K3 | Yearly equality of person × notebook counts, derived from the **actual distribution count D** | mandatory |
| K5 | Notebook-group balance per quarter | optional preference |
| K6 | "Weekly special" notebooks (default 1, 3, 6) never go to the same person in consecutive months | mandatory |
| K7 | Staff leave (single day or date range): a person whose leave covers at least a threshold share of a month (default 50%) is "absent" that month | input |

- **Equality uses D:** D = total number of person-notebook assignments actually made. A person's target share is `D · available months / total available months`; each notebook gets `D / N`. Without leave, D = N·M and this equals the classic ⌊M/N⌋…⌈M/N⌉ rule.
- **Open notebooks:** when staff are absent, spare notebooks are either given to available people as extras (default, at most 2 per person per month, everyone present gets at least one) or left open.
- **Screens:** R0 start wizard (feasibility card) → R1 stepped parameters (period, rules, staff & notebooks, leave, special conditions, summary) → R2 generation → R3 review (colour-coded plan, count/hand-over heat-maps, validation report, click-to-swap with live rule impact, "re-plan" on violation) → R4 approval & outputs.
- **Outputs:** `defter_plani.csv` (`yil, ay, calisan_id, defter_no, durum`), `izin_ozeti.csv`, `dogrulama_raporu.json`, `parametreler.json`, `sayim_matrisi.csv`, `devir_matrisi.csv`, ZIP.
- The same seed and inputs always give the same plan.

Measured on the reference setup (M = 12, G = 2): N = 4–11 reach the theoretical hand-over lower bound within milliseconds; N = 12–15 reach it +1; N = 3 with G = 2 has no solution (use G = 1).

## Data formats

CSV column names, JSON keys and file names are a stable schema and are **not translated**, whatever the UI language is. Delimiter (`,` or `;`) is auto-detected; UTF-8 and Windows-1254 are accepted.

```csv
# calisanlar.csv
calisan_id,ad_soyad,rol,il,ilce,donemlik_kapasite,musait_oran,kir_gorevi_yapabilir,aktif,kapasite_notu
# isler.csv
is_id,il,ilce,mahalle,yerlesim_tipi,birim_no,gorusme_sayisi,onceki_ay_gorusen_calisan_id,oncelik,anket_turu
# izinler.csv (v2 leave)
calisan_id,baslangic,bitis,not
```

Boolean values accept `Evet/Hayır` (also yes/no/true/false/1/0); `yerlesim_tipi` is `Kent` or `Kır`; `oncelik` is `Yüksek`, `Normal` or `Düşük`; leave dates are `YYYY-MM-DD` or `DD.MM.YYYY`.

## Project structure

```
src/
  app/            Next.js App Router entry
  components/     shell, Excel-style DataTable, modal confirm dialogs, UI primitives
  screens/        Home (engine selection) and v1 screens 0–8
  lib/            v1 engine, CSV parsing/validation (PapaParse + Zod), store, report, outputs

```

Stack: Next.js (App Router) + TypeScript, Tailwind CSS, Zustand, PapaParse, Zod, Recharts, JSZip, Radix Dialog, Vitest.

## Internationalisation

All UI text lives in `src/i18n/dict/*.ts` (six languages per key). Use `useT()` in components and `tx()` elsewhere; see [`docs-i18n.md`](docs-i18n.md). `npm test` fails if a key is missing in any language, placeholders differ, or code references an unknown key. `node scripts/i18n-scan.mjs [path]` lists remaining hard-coded Turkish text.

Known limitations: event-log and validation messages are stored in the language active when they were produced; translations are machine-written and should be reviewed by a native speaker before official use.

## Limitations and next steps

- Linking a rotation plan to v1 (a "follow the notebook plan" rule using a `defter_no` column) is not implemented yet.
- v2 leave is month-based (threshold rule); week-level handling is not implemented. Notebook weights are not used in equality.
- Adding leave after a plan was generated regenerates the whole plan; "keep past months fixed" is not available yet.
- The search runs on the main thread (with progress and cancel); a Web Worker would help for large N.
